# Differences from HiFiBerryOS

HiFiBerryOS is Raspberry Pi OS (Debian) with HiFiBerry's packages. This flake
reproduces the same components and the same wiring on NixOS. Where Debian
mechanisms do not exist on NixOS, this is how they are handled.

## Users and services

HiFiBerryOS runs PipeWire and all players as *user* services of the user that
ran `install-all` (recorded in `/etc/hifiberry.user`), with lingering enabled so
they start at boot. The module does the same for `hifiberry.user` (default
`hifiberry`): `users.users.<user>.linger = true`, the same supplementary groups
(`audio video render input gpio i2c spi plugdev`), and the player units are
installed as systemd user units with an `[Install]` section.

System services (`config-server`, `config-detect`, `audiocontrol`,
`audiocontrol-metadata`, `hifiberry-auth`, `nginx`, `sigmatcpserver`,
`roomeq-server`, `hifiberry-bluetooth`, `nqptp`, `volume-store.timer`,
`volume-restore`, `sambamount`, `create-uuid`, `ble-provisioning`) are ordinary
NixOS systemd services, with the same users (`audiocontrol`, `roomeq`, …) and
the same unit settings as the Debian packages.

## Enabling and disabling players

A Debian package enables its player's user unit with `systemctl --global` when
installed, and the configurator toggles players the same way. On NixOS
`/etc/systemd/user` is read-only, so:

- `hifiberry-player-defaults.service` runs once per player (a marker in
  `/var/lib/hifiberry/player-defaults/`) and enables the unit in the player
  user's own configuration (`~/.config/systemd/user/default.target.wants`),
  which is what `hifiberry.players.<name>.autoStart` controls.
- `configurator` is patched (see `pkgs/configurator/default.nix`) to run
  `systemctl --user enable/disable` as the player user instead of
  `systemctl --global`, so the switches in the web interface keep working and
  the state persists across reboots and rebuilds.

## Extensions

The web interface's "Extensions" page lists packages marked
`Hifiberry-Extension: yes` in HiFiBerry's apt repository and installs them with
apt. There is no apt here: the players are options
(`hifiberry.players.*`), and the configurator is patched to read
`/etc/hifiberry/nixos-extensions.json`, which the module generates from the
enabled players, so the page shows them as installed. Installing from the UI
is not possible; change the configuration and rebuild.

## config.txt and sound card detection

`config-configtxt --default-config` disables the onboard and HDMI audio and
enables I2C and SPI; `config-detect --store --reboot` writes the detected
card's `dtoverlay=` line into `/boot/firmware/config.txt` and reboots.

On NixOS `config.txt` is generated by nixos-raspberrypi from
`hardware.raspberry-pi.config` on every `nixos-rebuild switch`. The module sets
the HiFiBerry defaults there (`dtparam=audio=off`, `i2c_arm=on`, `spi=on`,
`vc4-kms-v3d,noaudio`) and appends `include hifiberry.txt`. The configurator is
patched to treat `/boot/firmware/hifiberry.txt` as its config.txt, so
everything it writes at runtime (overlay, `# HiFiBerry card:` comment,
detection-disabled marker, USB gadget mode) survives rebuilds.

Set `hifiberry.soundcard = "hifiberry-dacplus";` (any overlay name) to put the
overlay in `config.txt` itself. `config-detect` then only detects and logs, and
the first boot does not need to reboot.

## /usr/share/hifiberry

The components read players.d, features.d, DSP profiles, speaker presets and
RoomEQ signals from `/usr/share/hifiberry`. NixOS has no `/usr/share`, so a
tmpfiles rule points `/usr/share/hifiberry` at the merged `share/hifiberry` of
the installed packages (`hifiberry.internal.sharePackages`). `/etc/hifiberry/`
and `/etc/audiocontrol/players.d` are populated from the packages with
`environment.etc`.

## Hostname

NixOS normally manages `/etc/hostname` and points `systemd-hostnamed` at
read-only copies in `/etc/static`, so `hostnamectl set-hostname` fails. The
module leaves the hostname unmanaged instead (`networking.hostName = ""`), with
`DEFAULT_HOSTNAME=hifiberry` in `/etc/os-release` as the name until one is set,
and lets `systemd-hostnamed` write `/etc/hostname` and `/etc/machine-info`. The
setup wizard and the system settings then rename the device as on HiFiBerryOS;
a path unit restarts Avahi and Sendspin so they announce the new name.
NetworkManager is told not to take a hostname from DHCP.

Setting `networking.hostName` in the configuration fixes the name again; the
web interface can then only set the display (pretty) name.

## Firewall

Raspberry Pi OS runs no firewall, and AirPlay, Spotify Connect, Roon, Sendspin
and MPD need many ports; the module sets `networking.firewall.enable = false`
by default (`lib.mkDefault`, override it if you prefer).

## AudioControl credentials

`hifiberry-audiocontrol` is built from a `secrets.txt` that HiFiBerry does not
publish. Without it the daemons run, but Last.fm, TheAudioDB and the Spotify
account link fail at runtime. `hifiberry.audiocontrol.secretsFile` takes a
file in the format of `secrets.txt.sample` in the acr repository.

## Roon (RAAT)

HiFiBerry's `raat` repository is private and the Roon SDK is proprietary.
`pkgs/raat` downloads `hifiberry-raat_<version>_arm64.deb` from
`debianrepo.hifiberry.com`, patches the ELF binaries with autoPatchelf and uses
the wrapper scripts from hifiberry-os. It only exists for aarch64 and is marked
unfree; `nixpkgs.config.allowUnfreePredicate` is set for it when the player is
enabled.

## Kiosk mode and local displays

Not provided; the system is meant to be used through the web interface. The
`nowplaying-sdl` package is available for anyone who wants to wire up a
display themselves.

## Tailscale and other additions

Anything from the HiFiBerryOS docs that is plain Debian administration
(Tailscale, the power key behaviour, …) is ordinary NixOS configuration:
`services.tailscale.enable = true;`,
`services.logind.settings.Login.HandlePowerKey = "ignore";`.
